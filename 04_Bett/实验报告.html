广告素材合规审核 · 模型实验报告

数据：HuggingFace zjunlp/ChineseHarm-bench ｜ 测试集 956 条 ｜ 2026-10-15 ｜ 硬件：RTX 3050 Ti Laptop (4GB)

一、任务与数据

任务定义：广告素材投放前合规审核。输入一段文案，输出 6 类判定；模型没把握时输出「需人工复核」（置信度阈值拒判）。

  • 类别：0 不违规 / 1 黑产广告 / 2 欺诈 / 3 博彩 / 4 谩骂引战 / 5 低俗色情
  • 规模：去重后 9,503 条，分层抽样切分 train 7,600 / dev 947 / test 956
  • 测试集分布不均：低俗色情 201、谩骂引战 191、黑产广告 188、博彩 176、不违规 100、欺诈仅 100
  • 文本长度：中位数 19 字、平均 42 字 → max_len=64

四、类别加权实验：把欺诈召回从 77% 拉到 94%

问题：欺诈是少数类（测试集仅 100 条），无加权基线 26 条误判（11 条→黑产广告、9 条→博彩），召回仅 0.77。

方法：加权 CrossEntropyLoss，weight = √(N / (K·count))，开根号缓和过度补偿。实测权重：不违规 1.27、欺诈 1.26、黑产广告 0.92、博彩 0.95。

八、知识蒸馏：12 层 Teacher → 4 层 Student

Student 从哪来：本机只有 bert-base-chinese 一个预训练权重，没有现成的小中文 BERT，也不方便联网下载。所以采用层裁剪初始化——从 Teacher 的 12 层里按 uniform 策略等间隔抽第 [0, 4, 7, 11] 层，embedding / pooler / 分类头整块搬过来，再用蒸馏微调。只抽层、还没蒸馏时 macro-F1 只有 0.2445，蒸馏把它拉到 0.9230（+0.679）——这一栏最能说明蒸馏到底在干什么。

九、非结构化剪枝：50% 稀疏度

方法：全局 L1 幅度剪枝（magnitude pruning），分 3 步渐进到 50%，每步剪完立刻微调 1 轮让网络自我修复。只剪 Transformer 内的 Linear，跳过分类头和 pooler——它们参数量极小（768×6 / 768×768），剪了省不了空间却直接伤输出层。

关键认知：非结构化剪枝省的是「体积」，不是「速度」。稀疏度已经 50%，但存盘体积一点没变（390.2 MB）——因为权重只是被置 0，用 float32 稠密格式存盘时 0 和别的数占一样大的空间。真正的收益要到 gzip 之后才显现（-32.6%，叠加量化后 -72.9%）。CPU 耗时也几乎没变化，因为普通稠密算子不会跳过 0，必须配合稀疏计算库或专用硬件才有加速。

未剪枝基线的验证 F1 是 0.9441，所以剪枝是有代价的，只是代价很小：17% 时 -0.3 个点、33% 时 -1.1 个点、50% 时 -0.5 个点。曲线非单调（33% 反而最低）是因为每步只微调了 1 轮、修复程度不同。关键点在于：剪掉一半权重，验证 F1 只掉 0.5 个点，说明这个 12 层模型在广告审核任务上明显过参数化，冗余度很高。
踩过的坑：别用 PyTorch 的 prune.global_unstructured 做迭代剪枝。它给每个 Linear 挂上 weight_orig + weight_mask 两份 85M 的全精度缓冲，显存凭空多出约 0.68 GB。本机只有 4 GB 且被浏览器等常驻程序分走一部分，实测直接触发 WDDM 换页，训练速度从 6 it/s 掉到 0.05 it/s（20 秒一个 batch）。改成手动维护掩码（阈值在 CPU 上算，原地置 0，每个 optimizer.step() 后重新压制）后恢复 5.7 it/s，快了 100 倍。
另外它的 amount 是「在当前尚未被剪的权重中再剪掉的比例」而非累计比例，实测直接传 [1/6, 2/6, 3/6] 会复利叠加成 16.67% → 44.44% → 72.22%，第三步远超计划的 50%。

十、本次改造修复的工程问题（10 个）

  • config.device 被二次赋值硬编码成 cpu → 有显卡也永远跑 CPU；拆出 quant_device 修复
  • train() 无 return 且指标只在最优轮追加 → 训练曲线只有 1 个点甚至 None
  • test_dataloader drop_last=True 丢尾部样本 → 测试指标不可信
  • lr=2e-4 与注释 2e-5~5e-5 不符 → 回归 2e-5
  • rf_train.py 被 IDE 误插入 from pygments.lexer import words → 启动即崩
  • fastText 打不开中文路径（C++ 窄字符内核，路径含「深度学习」必崩）→ 加 ASCII 临时目录兼容层
  • fastText 自动调参挑到大 dim，输入矩阵 11GB 撑爆内存且无 Python 异常 → 加体积上限
  • 量化脚本 device 撞车（本报告第七节）
  • 迭代剪枝用 PyTorch prune 缓冲导致显存膨胀、触发 WDDM 换页，速度掉 100 倍 → 改手动掩码（本报告第九节）
  • 蒸馏 alpha=0.5 让不带类别权重的 KL 稀释硬损失，欺诈召回从 0.94 回退到 0.77 → alpha 提到 0.7（本报告第八节）

十一、遗留与下一步

  • 谩骂 ↔ 低俗色情边界（24 条混淆）：可引入二阶段细分类或更换标注口径
  • 黑话变形字（米/柏/薇/丝信）：fastText 字级天然占优；BERT 可加对抗增强或黑话词典
  • DeepSeek 对照实验：提示词已就绪（6 类定义 + 消歧规则 + 12 条 Few-Shot + 拒判），配置 DEEPSEEK_API_KEY 后可量化回答「这个场景值不值得上大模型」
  • 欺诈标注质量：建议抽 100 条欺诈/博彩边界样本人工复核，是比调参更划算的投入
  • Student 的欺诈召回仍是 0.83（Teacher 0.94）：可尝试 6 层 Student、更高 alpha，或只对非欺诈类做蒸馏、欺诈类保留 Teacher
  • 结构化剪枝：本节是非结构化（只置 0），若想真正拿到推理加速，应做 attention head / FFN 维度的结构化裁剪，再配合稀疏算子
