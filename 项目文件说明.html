零、这个项目在做什么

一句话：输入一段广告文案，输出它属于哪一类违规（或不违规），并在模型没把握时转人工复核。

技术上它是一条完整的文本分类流水线，同一份数据喂给四套方案横向对比，再叠加模型压缩（量化 / 蒸馏 / 剪枝），最后通过 Flask 服务 + Streamlit 页面交付。

二、理解全部代码的关键：数据契约

四套方案能共用同一份原始数据，靠的是两条极简约定。理解了它们，其余代码基本是复制粘贴。

契约一：数据文件格式

01-data/train.txt      每行：文本 \t 标签索引
01-data/dev.txt        例：加薇xxx看片\t5
01-data/test.txt
01-data/class.txt      第 i 行 = 标签 ID 为 i 的类别名（行号即 ID）

契约二：推理函数签名

predict_fun(data: dict) -> data    # data['text'] 进，data['pred_class'] 出

四套方案的 predict_fun 签名完全一致，所以 Flask 服务只需改一行 import 就能换模型。

十、四个必须知道的坑

1. 端口冲突

02-rf、03-fasttext、04_Bett 的 API 端口都是 6000，同一时间只能起其中一个。想同时对比要手动改各自 config.py 里的 api_port。05-LLM 是 5002，不冲突。

2. 项目路径不能改

fastText 的 C++ 内核读不了中文路径，全靠 03-fasttext/config.py 里的兼容层把读写搬到 %TEMP%。若把项目挪到别的中文目录，理论上仍可用，但不要绕过这个兼容层直接传路径。

3. batch_size 不要设 16

本机是 RTX 3050 Ti（4GB 显存），且浏览器、微信常驻占用。batch=16 会触发显存换页，速度掉到 1 it/s 以下；设 8 可稳定在 6 it/s。

4. 不要用管道跑训练

python bert_train.py | grep xxx 会卡死——tqdm 用 \r 刷新进度且从不换行，管道会把所有进度攒成一行堆在内存里。正确做法是重定向到文件：python bert_train.py > train.log 2>&1，再用 tr '\r' '\n' < train.log 查看。
