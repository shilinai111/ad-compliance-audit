知识蒸馏：alpha 消融

Teacher 12 层 → Student 4 层
配置accuracymacro-F1欺诈召回
alpha=0.5, 3 epochs0.91530.91330.77
alpha=0.7, 5 epochs（最终采用）0.92470.92300.83
踩过的坑：alpha 别照抄论文的 0.5。软损失 KL 本身不带类别权重，它占一半话语权时会把少数类判别拉平——上一步类别加权换来的欺诈召回（0.94）直接掉回 0.77。提到 0.7 后硬损失重新主导，召回回到 0.83。

口径与陷阱（汇报时容易被追问的点）

RF 用了不同切分
实验报告注明随机森林使用「自带 8:2 切分」，与其它方案的统一测试集不同源，因此 0.784 / 0.780 不能直接横向比较。
延迟有三个口径
模型前向 5.19ms（脚本内 100 次平均）／CPU 端到端 103ms（四方案表）／CPU 单条 63.6ms（剪枝表）。同一份报告里就有两个 CPU 数字，汇报时应指明取自哪张表。
剪枝的 CPU 数字自相矛盾
剪枝表记录原始 63.6ms、剪枝后 49.7ms（看起来更快），但正文说明非结构化剪枝在稠密算子上不应期待加速。合理判断是测量波动，而不是真实加速。

接口与部署

四条路线都是 POST /predict 的 JSON 接口。字段并不统一，前端已做兼容归一。

端口已重新分配（原设计有个坑）：三条路线原本都用 6000，这会同时踩两个问题——① 三个服务互相抢端口，同一时间只能起一个；② 6000 在 Chromium（Chrome / Edge）的受限端口名单里，浏览器会直接拒绝连接并报 ERR_UNSAFE_PORT，前端页面永远连不上，而 curl 不检查该名单，所以命令行测试会「看起来一切正常」。现已改为：BERT 8000 / 随机森林 8001 / fastText 8002，大模型仍为 5002 —— 互不冲突且都可被浏览器访问。
