# 广告素材合规审核工作台（06-web）

一个**纯静态单文件**的审核工作台，用来取代 `02-rf` / `03-fasttext` / `04_Bett` / `05-LLM` 里四个各自独立的 Streamlit 演示页。

---

## 30 秒上手（照抄即可）

> **关键认知：前端不需要「启动」。** 它就是一个 HTML 文件。真正要启动的是**后端服务**；前端由后端顺带托管出来。

```cmd
:: ① 先确认 8000 端口没被别的程序占着（这条命令"无输出"才是干净的）
netstat -ano | findstr :8000

:: ② 启动后端（这个窗口要一直开着）
cd /d D:\pythondm\深度学习\code\04_Bett
D:\anaconda2024\envs\DeepLearning\python.exe api_flask_server.py

:: ③ 看到这行就成功了
::    * Running on http://127.0.0.1:8000
```

然后**在浏览器地址栏输入**（不是双击文件！）：

```
http://127.0.0.1:8000/
```

右上角徽章显示 **「接口在线」** 就对了，输入「蠢猪」应得到 **谩骂引战 98.7%**。

> ⚠️ **不要双击 `index.html` 来演示**：`file://` 打开时浏览器会拦掉对 `127.0.0.1` 的跨域请求，页面会退回「离线兜底」，结论就变成内置规则的 56.4% 而不是模型的 98.7%。

## ⚠️ 端口必须避开 6000（本项目踩过的大坑）

**`6000` 在 Chromium（Chrome / Edge）的受限端口名单里**（它是 X11 的端口）。浏览器会**直接拒绝连接**并报：

```
ERR_UNSAFE_PORT
```

后果非常隐蔽：

| 现象 | 原因 |
|---|---|
| 页面一直显示「离线兜底」 | 浏览器**永远连不上** `127.0.0.1:6000`，`fetch` 直接失败 |
| 但命令行测试一切正常 | `curl` / `requests` **不检查**这份受限端口名单，所以返回 200 |

也就是说，**用命令行验证"接口没问题"完全证明不了浏览器那侧能用**。这个坑害得排查了好几轮，务必记住。

因此本项目已把端口全部改为浏览器安全端口，并且顺带解决了「三条路线抢同一个端口」的问题：

| 路线 | 端口 | 说明 |
|---|---|---|
| **BERT**（最终采用） | **8000** | `04_Bett/config.py` 的 `api_port` |
| 随机森林 | **8001** | `02-rf/config.py` |
| fastText | **8002** | `03-fasttext/config.py` |
| 大模型（DeepSeek） | **5002** | `05-LLM/api_flask_server.py` 硬编码（5002 不在受限名单里，无需改） |

改端口后**三个服务可以同时启动**，互不冲突。

## 打开方式（推荐同源打开）

**推荐**：先启动 BERT 服务，再用浏览器打开 **http://127.0.0.1:8000/** —— `04_Bett/api_flask_server.py` 加了根路由 `/`，会直接把本工作台托管出来。前端与接口**同源**，不触发任何跨域预检，演示时最稳。

**也可以**直接双击 `index.html`：纯静态单文件，无构建、无 npm 依赖、无 CDN 引用，断网也能打开；但要连真接口时会走跨域请求（已加 CORS 与私有网络预检头，通常可用，只是多一层依赖）。

> 同源打开时前端会**自动识别**接口地址（判断依据：`GET /predict` 返回 `405` 说明对面是真正的 Flask 接口），所以换成任何端口都不用手工配置。

## 两种数据来源

| 模式 | 说明 |
|---|---|
| **真实接口** | 默认请求 BERT `http://127.0.0.1:8000`、随机森林 `8001`、fastText `8002`、大模型 `http://127.0.0.1:5002`，可在右上角「设置」里逐个修改地址。其中 BERT 会额外返回六类 `probs`，概率条是真实分布；其余三条路线只返回 `pred_class`，没有置信度也没有概率分布。 |
| **离线兜底** | 接口超时、报错或跨域被拦截时自动启用；也可在设置里强制开启。结果由**内置关键词规则**生成，结论中会明确标注「内置规则 · 非模型推理」，并在提示里说明回退原因，不会伪装成模型输出。 |

本机实测可用的解释器是 Anaconda 的 `DeepLearning` 环境（torch / transformers / flask 齐备）：


然后回到本页面**刷新一次**：右上角状态徽章会从「离线兜底」变成「接口在线」，结论右侧的标记会从「内置规则 · 非模型推理」变成「真实接口」。

> **实测真模型与内置规则的差距**（同一输入，用于说明兜底为什么只是兜底）：
>
> | 文案 | 真模型（BERT） | 内置规则兜底 |
> |---|---|---|
> | 蠢猪 | 谩骂引战 **98.7%** | 谩骂引战 56.4% |

| 随机森林 | **8001** | ✅ 可用 | `rf_model.pkl` 85MB + `tfidf_model.pkl` 234KB（已由 `rf_train.py` 训练生成） |

各开一个终端窗口分别启动，**可以同时开着**：

> **四条路线现在都返回六类概率**（`probs`）与置信度拒判（`confidence` / `need_review` / `raw_class`）。但它们的**概率来源与尺度互不相同，阈值必须分别标定**；其中大模型是**模型自报分数、未经校准**，不能与前三者相提并论：
>
> | 路线 | 概率来源 | 实测特征 | 同一批文案下阈值 0.60 的效果 |
> |---|---|---|---|
> | BERT | softmax | 分布较平滑 | 偶尔拒判（中性文本 0.37 → 转人工） |
> | 随机森林 | 200 棵树投票比例 | **偏保守**，常见 0.4~0.8 | **大量拒判**（蠢猪 0.42、代办 0.58、彩票 0.54 全部转人工） |
> | fastText | 6 类归一化得分 | **极度饱和**，常 0.98~1.00 | **基本不拒判**（蠢猪 1.000、彩票 1.000） |
> | 大模型 | **模型自报分数（未校准）** | 强特征 0.72~0.95；模糊时接近均分 | 偶尔拒判（过短文本「好」给 0.25+0.15×5 均分 → 转人工） |

> ⚠️ 两个训练脚本的注意事项：
> - `rf_train.py` 用 `n_jobs=-1` 多核训练；**在受限沙箱里会因禁止命名管道而报 `PermissionError`**，普通终端 / PyCharm 里没有这个问题。若确实受限，可先设环境变量 `JOBLIB_MULTIPROCESSING=0` 再跑。
> - `fasttext_char_default.py` 训练很快，但**日志里会打印整个词表**，建议重定向到文件：`python fasttext_char_default.py > ft_train.log 2>&1`。

## 六个功能区

1. **审核工作台** — 单条审核：类别判定 + 置信度 + 处置建议（自动通过 / 自动拦截 / 转人工复核）+ 六类概率条；右侧「最近审核记录」显示最近 8 条，点击可回填。
2. **批量审核** — 粘贴文本，或**上传文件**（`.txt` / `.csv` / `.tsv` / `.json`，拖放或点选，自动识别 UTF-8 与 GBK）。一行一条；若文件是 `文案⇥标签` 两列，会顺便算出**与标签的一致率**。可按处置筛选、按置信度排序、导出 CSV。
3. **审核记录** — **单条审核与批量审核的结果都会写进这里**：时间 / 路线 / 方式（单条，或「批量」并显示批次文件名）/ 文案 / 判定类别 / 置信度 / 处置 / 来源。**处置列按当前阈值实时重算**，拖动顶部滑块历史结论一起变；支持按处置、路线、方式、来源四重筛选，可导出 CSV、可清空。记录保存在浏览器 localStorage（刷新不丢，上限 1000 条），点任意一行可回填到工作台。
4. **指标看板** — 真实指标 KPI、六类样本占比、类别加权收益与代价、真实混淆矩阵、阈值拒判实验。
5. **方案对比** — 四路线横向对比 + 量化 / 蒸馏 / 剪枝的压缩前后对比 + alpha 消融 + 稀疏度阶梯 + 口径陷阱说明。
6. **接口与部署** — 四条接口的请求/响应示例（可一键复制）、字段差异表、启动命令、跨域说明。

## ⚠️ 数据口径（汇报时最容易翻车的点）

1. **README 写错了准确率**：README 第 3.1 节「BERT 微调（最终）准确率 0.9331 / Macro-F1 0.934」有两处问题——
   - `0.9331` 是 `04_Bett/train_results.json` 里的 **`val_f1`（macro-F1）**，不是准确率（同文件末轮 `val_acc` = `0.9311`）；
   - 这两条来自 **dev 验证集（947 条）**，不是测试集。
   - 本工作台统一采用**实验报告口径：accuracy 0.9310 / macro-F1 0.9343**。
2. **随机森林用了不同切分**：实验报告注明 RF 使用「自带 8:2 切分」，与其它方案的统一测试集不同源，因此 `0.784 / 0.780` 不能直接横向比较。
3. **延迟有三个口径**：模型前向 `5.19ms`（脚本内 100 次平均）／CPU 端到端 `103ms`（四方案表）／CPU 单条 `63.6ms`（剪枝表）。同一份报告里就有两个 CPU 数字。
4. **剪枝的 CPU 数字自相矛盾**：剪枝表记录原始 63.6ms、剪枝后 49.7ms（看起来更快），但正文说明非结构化剪枝在稠密算子上不应期待加速。合理判断是测量波动。
5. **非结构化剪枝不省速度只省 gzip 体积**：50% 稀疏度下存盘体积不变（390.2MB），gzip 后 362.3 → 244.3MB 才是真实收益。
6. **置信度尺度不可直接比较**：BERT 是 softmax、随机森林是 200 棵树投票比例、fastText 是 6 类归一化得分、大模型是**自报且未校准**的分数。同样显示 `0.60`，含义并不相同——实测同一批文案下，阈值 0.60 会让随机森林拒判 3/4 条，而 fastText 几乎一条都不拒（概率常年 0.98~1.00）。汇报时应**分别标定阈值**，或只在同一条路线内纵向比较。大模型的分数尤其只能看相对大小（例如「代办证件」黑产 0.72 / 欺诈 0.20 说明它在两类间犹豫），**不能解读为"有 72% 的把握"**。

## 跨域（CORS）

**首选方案是绕开跨域**：`04_Bett/api_flask_server.py` 已加根路由 `/`，直接访问 <http://127.0.0.1:8000/> 就是同源，根本不存在预检问题。

如果坚持用 `file://` 双击打开，页面访问 `http://127.0.0.1:8000` 属于跨域：浏览器会先发 `OPTIONS` 预检，Chrome 还可能追加「私有网络访问」预检。原始 `api_flask_server.py` 只允许 `POST` 且不返回 CORS 头，调用会被拦截。已为四个服务加上最小化 CORS 支持（`@app.after_request` 回写头 + 放行 `OPTIONS` + `Access-Control-Allow-Private-Network`，**不引入任何新依赖**）。若仍被拦截，页面会自动回退到离线兜底并明确提示。
